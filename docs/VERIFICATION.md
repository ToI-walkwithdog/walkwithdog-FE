# 검증 현황

단계마다 갱신한다. "확인"은 실제 기기와 로컬 BE로 본 것이고, "미확인"은 아직 보지 못한 것이다.
승인 상태 화면은 보호소 테스트 계정과 승인 API로 나중에 확인한다(DB를 직접 바꾸지 않는다).

## 6단계 내 예약, 취소 (8-1~8-8)

### 기기에서 확인함
- 내 예약 목록 불러오기와 "승인 대기" 카드 표시(시각은 KST)
- 대기 중인 예약 취소 흐름(8-4 → 8-7 → BottomSheet 확인 → 8-8)
- 취소 뒤 목록의 "지난 예약" 탭 반영
- 이미 취소된 예약의 안내 문구(409 `REQUEST_ALREADY_CANCELLED`)

### 미확인
- 승인 상태 화면: 8-3 상세, 승인 뒤 취소, 보호소 코드 입력으로 이동(보호소 계정과 승인 API 필요)
- 취소 오류 경로: `CANCEL_TIME_EXPIRED`, `WALK_RECORD_EXISTS`, `REQUEST_STATE_CONFLICT`, `REQUEST_LOCK_CONFLICT`
  (`REQUEST_ALREADY_CANCELLED`는 API 재전송으로 따로 확인한다)
- 한 페이지(20건)를 넘는 목록: 더보기, offset을 원본 개수만큼 더하는 동작, 예약 ID 중복 제거
- 403과 404 처리: HTTP 상태로만 나눈다. 나이 확인 대기 계정은 `GET /users/me`의 단계로 판단한다.
- 확정 탭에 산책을 마친 예약이 "산책 완료"로 보이는지

## 7단계 보호소 코드, 시작, 산책 중, 신고, 종료 (4-x, 5-x)

구현했고 타입 검사만 통과했다. 보호소 테스트 계정이 코드를 발급하고 예약을 승인해야 끝까지 갈 수 있다.

### 기기에서 확인함
- 없음

### 미확인: 산책 정책 (BE 담당자 확인 사항)
- 화면 잠금 뒤 돌아오기: 서버 상태 확인(`GET /walks/active`), 큐와 순번 맞추기, 정지가 아니면 GPS 다시 시작
- 일시정지 중에도 시간이 계속 늘어나는지(정지 시간을 빼지 않는다), 같은 `walk_id`가 유지되는지
- 정지 중에 신고 메뉴나 마커 메뉴를 열고 닫아도 기록 상태가 바뀌지 않는지
- 좌표 순번이 0부터 연속인지, 전송 실패 뒤 같은 순번으로 다시 보내는지, 서버가 이미 저장한 순번은 큐에서 빠지는지
- 정지와 재개 사이의 간격을 선으로 잇지 않는지(좌표를 만들지 않는다)
- 같은 마커 요청을 다시 보내도 하나만 저장되는지(같은 `client_marker_id`), 위치 없는 마커(`MARKER_LOCATION_UNAVAILABLE` 안내)
- 자동 종료 뒤 좌표 전송이 막히는지, 자동 종료 안내 문구와 6-1 이동, 보내지 못한 좌표 수 안내
- 종료 응답이 유실됐을 때 같은 산책의 상세로 확인하는지
- 세션 만료 뒤 다시 로그인하면 같은 산책으로 돌아오고 큐가 유지되는지
- 기기 시계가 서버보다 앞서거나 뒤일 때의 좌표 전송(아래 참고)
- 보호소 코드부터 종료까지 실제 기기 전체 흐름(코드 확인, 틀린 코드, 5회 잠금, 시작, 산책, 신고, 종료)
- 마커 4종(포토스팟은 `OTHER` + 메모), 신고 5종과 기타, 신고 실패 뒤 "다시 전송하기", `DUPLICATE_RECENT` 확인
- GPS 끊김 자동 안내(30초 무신호)와 위치 다시 연결, 위치 권한 거부
- 앱 재시작 뒤 홈에서 진행 중인 산책 복구
- 예약 취소 뒤 목록 캐시 무효화(6단계): 취소 뒤 뒤로 돌아간 목록이 첫 페이지부터 다시 불러와지는지

### 알려진 한계
- 앱이 foreground일 때만 위치를 모은다. 백그라운드에서는 수집이 끊기고 서버가 새 좌표 없이 1시간이 지나면 자동 종료한다.
- 보내지 못한 좌표 큐는 메모리에만 있다. 앱 프로세스가 종료되면 사라진다(저장소 도입 여부는 별도 결정).
- 지도는 목업 그림이고 실제 경로는 그리지 않는다. 6-x 이후 화면은 목업이다(8단계). 종료 결과는 `getEndedWalk()`에 남는다.

### 기기 시계와 좌표 시각
좌표의 `recorded_at`은 기기가 위치를 얻은 실제 시각 그대로 보낸다. 서버는 시작 이후, 서버 현재 시각 이하만 받고
위반하면 batch 전체를 409로 거절한다. 기기가 앞서면 서버 시각이 그 시각을 지날 때까지 큐에 두고, 뒤면
시작 이전 관측은 보내지 않는다. 서버 시각은 `GET /walks/active`의 `elapsed_seconds`로 추정하고 5분마다 다시 맞춘다.
