# 보호소 모바일 웹: 화면 및 백엔드 전달 문서

이 문서는 **현재 구현된 목업**을 설명하며 확정된 API 계약이 아닙니다. 영문 원본은 [SCREEN_HANDOFF_EN.md](./SCREEN_HANDOFF_EN.md)입니다. 웹 UI는 봉사자 Expo 앱과 분리된 모바일 중심 React/Vite 프로젝트이며, 단색 화면은 피그마 디자인이 아닙니다.

## 공통 동작 및 범위

- `shelter-web`에서 `npm run dev`로 실행하고 `npm run build`로 타입 검사와 빌드를 수행합니다. URL 해시로 이동하며 직접 링크와 브라우저 뒤로/앞으로 가기를 사용할 수 있습니다.
- 초기 보호소·강아지·일정·예약·신고·산책은 예시입니다. 상태는 같은 탭의 화면끼리 공유하는 브라우저 메모리에만 유지됩니다. 새로고침이나 탭 종료 시 초기화되며 대시보드 종료만으로는 초기화되지 않습니다. 설정에서 확인 후 초기화할 수 있습니다.
- 서버 요청은 없으며 봉사자 앱과도 동기화되지 않습니다. 실제 계정 정보, 개인정보 또는 민감한 사진을 입력하지 마세요.
- 공통 헤더의 이전 버튼은 브라우저 기록이 아니라 정해진 화면으로 이동하고 홈 링크는 대시보드로 이동합니다. 잘못된 해시나 없는 기록 ID에는 오류와 복귀 경로를 표시합니다. 브라우저 뒤로/앞으로 가기는 해시 기록을 따릅니다.
- “목업” 버튼은 예시만 변경합니다. 서버 인증·인가·저장·업로드·승인·알림·코드·실시간 감지·신고·평가는 **구현되지 않았습니다**. 성공 문구도 로컬 미리보기 상태만 뜻합니다.

## 화면 목록

### 1. 로그인 (`#login`, 해시가 없는 주소도 동일)

**목적과 흐름:** 계정 아이디와 비밀번호 입력, 로그인, 대시보드 미리보기, 보호소 인증 안내 링크를 제공합니다. 브라우저에서 두 입력을 필수로 확인합니다. 로그인 제출은 미연결 안내만 표시하며 계정 정보를 전송하지 않습니다. 미리보기는 인증 없이 `#dashboard`로 이동합니다.

**백엔드 전달:** 계정 발급, 인증 방식, 계정 복구, 세션 만료, 로그아웃, 로그인 실패 처리를 정해야 합니다. 미리보기와 인증 없는 직접 링크는 운영 환경의 접근 제어가 아닙니다.

### 2. 보호소 인증 (`#verification`)

**목적과 흐름:** 인증 방식·필요 서류·승인 기준이 미정임을 안내합니다. 이전은 로그인, 홈과 미리보기는 대시보드로 이동합니다. 신청서, 업로드 및 제출 기능은 없습니다.

**백엔드 전달:** 신청 항목, 증빙 서류, 접수·검토 상태, 재신청, 관리자 심사, 심사 중 접근 권한, 거절 사유, 안전한 서류 처리를 정해야 합니다. 현재 실제 인증 상태는 모델링하지 않았습니다.

### 3. 대시보드 (`#dashboard`)

**목적과 흐름:** 예시 보호소 이름·지역, 미리보기 안내, 승인 대기 건수, 확인 불가인 산책 중 건수(`—`), 미확인 접수 신고 건수, 승인 대기 카드와 관리 메뉴를 표시합니다. 신청 카드는 상세로 연결되고 대기 신청이 없으면 빈 상태를 표시합니다. 종료는 로그인으로 돌아가며 목업 상태를 지우지 않습니다.

**백엔드 전달:** 보호소별 집계와 최근 처리 대상 신청을 제공하고 목록 페이지 처리, 로딩·빈 상태·오류를 지원해야 합니다. 실시간 건수는 신뢰할 수 있는 산책 상태에서 가져와야 하며 응답이 없다고 0으로 판단하면 안 됩니다. 데이터 갱신 주기와 알림 방식을 정해야 합니다.

### 4. 강아지 (`#dogs`, `#dogs/new`, `#dogs/edit/{id}`)

**목적과 흐름:** 예시 강아지의 사진 또는 대체 표시, 견종, 나이, 크기, 난이도와 등록/일시 중지 상태를 보여줍니다. 등록과 수정은 같은 양식을 사용하며 목록에서 로컬 상태를 전환합니다. 없는 ID는 오류를 표시합니다.

**입력:** 이름(필수, 최대 30자), 견종(필수, 40자), 나이(필수, 0 이상의 정수, 살), 크기(소형견/중형견/대형견), 난이도(필수, 0 이상의 수, 0.1 단위), 주의사항(선택, 500자), 사진(선택). 필수 텍스트가 공백만 있으면 거절합니다. 난이도의 척도와 의미는 **미정**입니다. 사진은 `image/*` MIME 타입이고 5 MiB 이하여야 합니다. 파일은 data URL로 메모리에 읽어 미리보기만 하며 제거할 수 있습니다. 읽기 오류를 표시하고 읽는 동안 저장을 막습니다. 저장은 목록으로 돌아가고 취소는 양식 수정을 버립니다.

**백엔드 전달:** 보호소 소유권, 생성/수정, 상태, 사진 업로드와 저장이 필요합니다. 서버 검증 및 실제 파일 내용 검사가 필요하며 브라우저 MIME·크기 검사는 편의 기능입니다. 필수 항목, 나이 표현, 난이도 범위, 파일 제한, 삭제·보존, 일시 중지가 기존 일정과 예약에 미치는 영향을 정해야 합니다. 지역과 보호소 이름은 강아지에 중복 입력하지 않고 보호소 정보에서 가져옵니다.

### 5. 산책 일정 (`#schedules`, `#schedules/new`)

**목적과 흐름:** 강아지별 날짜, 같은 날의 시작/종료 시간, 최대 산책 시간(분), 공개/일시 중지 상태를 표시하며 강아지가 중지 상태인 경우 안내합니다. 등록에는 활성 예시 강아지가 필요하고 없으면 강아지 관리로 연결합니다.

**입력:** 강아지, 날짜, 시작과 종료, 양의 정수 최대 산책 시간은 필수입니다. 종료는 시작보다 늦어야 하고 최대 시간은 전체 가능 시간 이하여야 합니다. 같은 강아지의 같은 날짜에 공개 일정이 겹치면 안 됩니다. 중지 일정을 재개할 때도 공개 일정과 충돌하면 거절합니다. 이 목업은 과거 날짜를 막거나 일정 중지 시 기존 예약을 확인하지 않습니다. 저장은 목록으로 돌아가고 취소는 입력을 버립니다.

**백엔드 전달:** 서버에서 트랜잭션으로 충돌을 검증하고 시간대, 과거 날짜 정책, 자정이 넘는 일정, 정원, 반복 일정, 수정/삭제 및 중지가 기존 신청·확정 예약에 미치는 영향을 정해야 합니다. 산책 시간이 고정인지 최대치인지 확정하고 봉사자 앱에 가능한 일정을 제공해야 합니다.

### 6. 예약 (`#bookings`, `#bookings/{id}`)

**목적과 흐름:** 예시 예약의 강아지, 신청자 이름·나이·산책 경험, 일정, 최대 시간과 상태를 보여줍니다. 목록이나 대시보드 카드에서 상세로 이동합니다. 대기 상태는 로컬에서 승인 또는 거절할 수 있고 다른 상태에는 처리 버튼이 없습니다. 대시보드 대기 건수도 변경됩니다. 없는 ID와 빈 목록은 안내합니다.

**백엔드 전달:** 보호소 범위의 신청과 권한이 허용된 신청자 정보만 제공하고 승인/거절을 원자적 상태 전이로 처리해야 합니다. 이미 처리·취소됐거나 충돌하는 신청을 다뤄야 합니다. 거절 사유, 취소 규칙, 정원과 알림을 정해야 합니다. 현재 승인은 보호소 코드 발급, 봉사자 알림, 정원 확보 또는 일정 가능 여부 검증을 하지 않습니다. 출시 전 봉사자 앱과 코드 발급·만료·검증을 협의해야 합니다.

### 7. 산책 현황 (`#live`)

**목적과 흐름:** 현재 산책, 위치, GPS 연결과 시간 초과를 확인할 수 없다는 상태를 명확히 표시합니다. 실제가 아닌 위치, 실시간 산책이나 경고를 만들어 표시하지 않습니다.

**백엔드 전달:** 산책 상태 전이, 보호소 범위 실시간 구독/폴링, 관측 시각, 오래된 데이터·오프라인 상태, 위치 정확도, 명시적 동의와 보존을 정해야 합니다. 시간 초과 기준, 알림 대상, 중복 방지와 복구 방식을 결정해야 합니다. 데이터가 없는 것을 산책 0건으로 해석하면 안 됩니다.

### 8. 신고 (`#reports`, `#reports/new`)

**목적과 흐름:** 봉사자 접수 예시와 보호소가 로컬에서 작성한 신고의 제목, 대상자, 강아지, 내용을 표시합니다. 미확인 접수 예시는 로컬 확인 처리할 수 있고 대시보드 미확인 건수도 변경됩니다. 작성 양식은 산책자(50자), 강아지(30자), 제목(80자), 내용(1,000자)을 모두 필수로 받으며 공백만 있는 값은 거절합니다. 저장은 목록으로 돌아가고 취소는 입력을 버립니다. 서버에 신고를 전송하거나 확인 처리하지 않습니다.

**백엔드 전달:** 자유 입력 이름 대신 서버 ID와 해당 산책 연결을 사용해야 합니다. 신고 유형, 시각, 증거, 상태 전이, 조회·수신 권한, 분류, 알림, 보존과 이의 제기를 정해야 합니다. 신고 내용은 민감하게 취급하고 보호소와 역할별 접근을 제한해야 합니다.

### 9. 산책 이력과 평가 (`#history`, `#history/{id}`)

**목적과 흐름:** 완료된 예시 산책의 강아지, 봉사자, 날짜, 시간, 거리, 산책 메모와 보호소 평가를 표시합니다. 상세 양식에서 비어 있지 않은 최대 500자의 평가를 로컬에 저장하며 서버 미전송 안내를 표시합니다. 없는 기록과 빈 목록은 안내합니다.

**인계:** 봉사자 앱의 인계는 산책 **종료 후** 강아지와 물품을 돌려줬는지 확인하는 절차입니다. 웹 목업에는 인계 상태나 확인 양식이 없으며 상세에서 확인할 수 없다고 명시합니다. 산책 완료만으로 인계 완료를 추론하면 안 됩니다.

**백엔드 전달:** 완료 산책 데이터와 단위, 기록 소유권, 페이지 처리, 수정 규칙과 보호소 열람 범위를 정해야 합니다. 평가 작성 시점, 수정, 봉사자 공개 여부, 보존 및 관리를 정해야 합니다. 봉사자의 산책 후 인계 결과를 저장해 보호소에 공유할지와 방법도 결정해야 합니다.

### 10. 보호소 설정 (`#settings`)

**목적과 흐름:** 예시 이름(필수, 80자), 지역(필수, 100자), 연락처(선택, 30자)를 수정합니다. 필수 입력이 공백뿐이면 거절하며 로컬 저장임을 안내합니다. 인증 링크는 안내 화면으로 이동합니다. 초기화는 브라우저 확인을 거쳐 모든 예시를 초기 상태로 되돌리고 대시보드로 이동하며 취소하면 변경하지 않습니다.

**백엔드 전달:** 권한에 따른 보호소 정보 수정과 감사 기록이 필요합니다. 전화번호 형식, 인증 상태, 직원 역할과 계정 수명 주기를 정해야 합니다. 초기화는 목업 전용이며 운영 데이터 삭제 API가 되어서는 안 됩니다.

## 제안 연동 범위 — 확정된 계약 아님

보호소, 직원, 강아지, 사진, 일정, 신청, 산책, 인계 결과, 신고, 평가에 안정적인 서버 ID와 보호소 소유권을 부여하는 방안을 제안합니다. 연동 후보는 인증 세션, 보호소 정보·인증, 강아지 CRUD/상태와 사진 업로드, 일정 관리, 신청 목록·상세·처리, 실시간 산책, 이력·상세, 신고 목록·작성·확인, 평가 작성·수정입니다. URL, HTTP 메서드, 요청·응답 형식과 오류 코드는 백엔드와 합의해야 합니다.

모든 변경은 서버에서 검증하고 최종 서버 상태를 반환하며 중복 제출을 막고 세션 만료, 권한 실패, 입력/충돌 오류, 네트워크 오류와 재시도를 처리해야 합니다. 실시간 정보는 관측 시각을 제공하고 누락·오래된 상태와 0건을 구분해야 합니다. 안전한 전송, 최소 수집, 역할·보호소별 인가, 감사 로그, 보존·삭제 정책과 명시적 위치 동의가 필요합니다. 봉사자의 나이·경험, 신고, 실시간 위치를 승인된 목적 외에 공개하지 않아야 합니다.

**미결정 제품 정책:** 보호소 인증, 난이도 척도와 난이도별 점수·레벨 기준, 일정 시간·중복·취소 규칙, 코드 수명 주기, 위치 동의와 시간 초과 기준, 산책 후 인계 책임, 평가 공개, 신고 처리, 데이터 접근·보존. 목업은 이를 확정하지 않습니다.
